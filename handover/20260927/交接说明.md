## 三、为什么有这份材料（背景，1 分钟读完）

初始需求是「分析两个项目，确认不足，出一份报告」。分析过程中发现两条**产品级**问题，值得先说明：

### 1. 有 4 个功能当前是「点了就崩」的状态

Windows 端 `web_api.py` 有 **6 个未定义裸名**，导致「立即检查更新 / 立即升级 / 升级开关 / 升级历史」这 4 个按钮**运行时必然 NameError**。已用 Python AST 静态分析实证，可复跑（见 `_verify_names.py`）。**修复只需补 `import time` + 5 处加模块前缀**，约 30 分钟。

### 2. 分析过程中推翻了一条会「弄坏产品」的错误建议

第一版方案曾建议「改用纯 HTTP 登录，把 WebView 路径降级为可选」。**这是错的**——git 提交 `ec9ffb9` 记录了真机实测：该校 AC 的终端归类不受 HTTP 参数控制，纯 HTTP 登录**必然失败**，WebView 是唯一可用路径。若按错误建议执行，该校用户将**全部无法上网**。

**教训**：这个项目的设计意图大量写在 **git 提交信息**里。执行前先跑
```powershell
git -C D:\Student_Workstation\Using_Workstation\campus-network-service\android log -1 --format=%B <相关文件最近提交>
```

**Q：`_verify_names.py` 是干什么的？**
A：用 Python AST 解析源码，找出「被引用但既未定义、也未通过 `globals()` 注入」的裸名。本项目的 `_attach()` 用 `globals()` 注入 27 个名字，导致常规静态检查和 IDE 都看不出跨模块引用错误 —— 这个脚本专门补这个盲区。P5-3 会把它接进 CI。

**Q：能不能直接开始改代码，不看文档？**
A：不建议。**§1 的 F1–F8 是「禁止推翻」清单**，其中 F1/F2 直接关系到「改了产品就不能用」。至少读完方案的 §0 和 §1（约 5 分钟）。

**Q：`任务总表.csv` 怎么用？**
A：UTF-8 BOM 编码，Excel 双击可正常显示中文；也可导入 Jira / Linear / 飞书多维表格。列：`ID / 阶段 / 任务 / 主要涉及文件 / 优先级 / 工作量 / 依赖 / 验收标准`。

**Q：这批文件会不会被误提交到项目里？**

## 十一、封包一律走 GitHub Actions

**原则**：所有「产出可分发文件」的动作都在 GitHub 上完成；本地只改代码 + 提交。两个仓库已内置完整封包链路（Inno Setup / 内嵌 Python / NSSM / apksigner 全在 CI 里），本机**无需**装打包环境。

| # | 产物 | 仓库 · workflow | 触发条件 | 取件位置 |
| --- | --- | --- | --- | --- |
| ① | Windows 安装包 `.exe` | `StardustFlashLink` · `Build Windows Installer` | 推 `main`（改 `**.md` 不触发）或手动 | Release `installer` |
| ② | Android APK | `DrcomAutoLogin` · `Build APK` | 推 `main` 或手动 | Release `debug` |
| ③ | **交接包 ZIP** | 两个仓库 · `Package Handover Bundle` | 推 `handover/**` 或手动 | Release `handover-<快照>` |

```powershell
# ① Windows 安装包

gh run watch  -R TSS-Small-sunshine/StardustFlashLink
gh release download installer -R TSS-Small-sunshine/StardustFlashLink -D .\dist

# ② Android APK
gh workflow run "Build APK" -R TSS-Small-sunshine/DrcomAutoLogin --ref main
gh run watch  -R TSS-Small-sunshine/DrcomAutoLogin
gh release download debug -R TSS-Small-sunshine/DrcomAutoLogin -D .\dist

# ③ 交接包 ZIP（封包前带凭据守卫：命中 p12 / keystore-credentials / 明文口令形态即拒绝封包）
gh workflow run "Package Handover Bundle" -R TSS-Small-sunshine/StardustFlashLink --ref main
gh release download handover-20260927 -R TSS-Small-sunshine/StardustFlashLink -D .\dist
```

**校验**（每个 Release 附件都可核）：交接包另附 `.sha256` 文件
```powershell

```

**封包红线**
1. 交付物以 **Release 附件 / Actions 制品**为准；本地 `packaging\build.ps1`、`gradlew assembleRelease` 只作离线排障，**不作为交付通道**
2. 不得用「手打 ZIP」当交付物：本地有、CI 没有 = 无法追溯、无法复现
3. release 说明与 commit message 里不得出现口令 / 私钥（§七 红线③）
