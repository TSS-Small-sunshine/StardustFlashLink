> **一句话**：这是 2.1 线的**升级链可靠性版** —— 把「升级已经成功、却被判失败并回滚」和
> 「回滚本身也救不回来」这两类最伤人的情况归因清楚；顺带修掉「在线状态未知被当成掉线」、
> 托盘消息循环被同步 HTTP 冻住、explorer 重启后图标永久消失等问题。
> 接口、配置结构、服务名 `AppId`、安装路径、密码文件格式**都没动** ✓ —— 老配置与升级路径不受影响 ✓。

## 🛡 本版修复

### ① 自动升级：不再「升完判失败 / 回滚白回滚」
- **升级前健康基线**：开始安装前先探一次本机 `/api/health`；当前服务就不健康时**中止升级**并提示
  先修服务（端口被占 / 配置非法时，装新版本也救不回来）。
- **回滚归因**：先看 `logs\service_stderr.log` 是否有 `FATAL`/`bind` → 判「端口被占」并**跳过回滚**；
  回滚后再探一次，仍不健康 → 标记 `rollback=USELESS`，界面明确说「回滚后仍不健康，可能需要人工处理」，
  **绝不再宣称回滚成功**。
- **升级结论延迟复核**：启动钩子以前只读一次执行器结果（结论常常还没写出来），现在 75 秒后再复核一次；
  启动钩子也从「端口绑定前同步等待」挪到绑定后的后台线程，慢机器不再因此被误判、误回滚。
- **失败的一次性计划任务会被删掉**（否则次日 00:00 会再静默装一遍）；`AppExit` 自愈同时校验 `Default` 与 `0`；
  预发布版本号（`-rc` / `-beta`）不再被判成「更新」；每个下载镜像下完**立即**校验 SHA-256，坏镜像自动换下一个。

### ② 连接判定与托盘
- **在线状态「未知」不再当「掉线」**：网关响应异常时不再照发登录请求（可能踢掉已在线会话），也不计入退避。
- JSONP 解析加固：服务端提示里带 `}` / `)` 不再截断解析。
- 托盘处理网络事件时不再在消息循环里同步发 HTTP（右键菜单 / 气泡不再卡顿）。
- **explorer 重启后托盘图标自动恢复**（任务栏重建时重新加入图标）。
- 周期线程退避到期改为最小等待，不再 0 秒空转刷日志。

### ③ 安装 / 卸载 / 发布
- 静默安装里的两处提示框补了静默守卫（无人在场时弹窗会让升级永久挂起）。
- 卸载时显式清理托盘自启值与偏好键（静默升级写入的值以前会残留，卸载后每次登录都报错）。
- 发布：同一分支的构建改为串行，且**只有 main 分支能发布 release**（其它分支只产出安装包 artifact）。

## ⚠️ 升级前须知

- **升级不覆盖用户数据**：`config.json`、`password.txt`（含各方案的 `password.<方案名>.txt`）
  与 `logs\` 都保留；安装器只在文件不存在时创建默认值。
- **服务名与安装路径不变**：仍是 `DrcomAutoLogin` 与 `%ProgramFiles%\DrcomAutoLogin`。
- 若本机 `nssm` 的 `AppExit` 曾被写成空值或被改成 `Restart`，服务下次启动会自愈为 `Default Ignore` + `0 Ignore`；
  也可用管理员执行一次 `nssm set DrcomAutoLogin AppExit Default Ignore`。
- 本版只改内部实现与错误处理，**配置格式与 API 字段没有变化**，无需迁移。

## 🔄 回滚

- 升级前会把代码文件整目录备份到安装目录的 `backup\<旧版本>\`（保留 7 天、至少 2 份）。
- 新版本起不来时执行器会自动回滚；也可在 Web UI「关于 → 更新 → 版本回滚」手动一键回退。
- 回滚**只动代码**，`config.json` / 密码 / 配置方案都不动。
- 如果界面提示「回滚后仍不健康」，说明问题不在代码版本（例如端口被占用），请按提示查看
  `logs\service_stderr.log` 或重新运行安装包。
