## 本版变更

### ✨ 新增（相对 v2.0.11.0）
- **日志不再无限长大**：业务日志超过 5 MB 自动轮转（保留 3 份旧档，合计 ≤ 20 MB），
  升级日志超过 2 MB 轮转（保留 2 份）—— 以前只能靠你自己去删。
  状态页「近 7 天」的统计会把旧档一起读，轮转不会让数字凭空变少。
- **一键诊断包（已脱敏）**：「关于 → 日志与诊断」里能看到各日志占用，并**一键下载诊断包** ——
  里面是版本 / 运行环境 / 服务状态 + 脱敏后的配置 + 各日志尾部（每个 ≤ 512 KB）。
  账号打码成「前 4 位 + ******」、MAC 打码、**不含任何密码**；校园网内网 IP 与 Wi-Fi 名会保留
  （排障需要），分享前请自行确认。反馈问题时发它，比截图 + 口述都准。

### ✨ 新增（相对 v2.0.10.0）
- **升级前备份整目录 + 升级失败自动回滚**：以前升级前只留一个 `联网_service.py` 的副本
  （还放在 `%TEMP%`），真要是新版本起不来，别的模块就回不去了 ✗。现在升级前会把**全部代码文件**
  备份到安装目录的 `backup\<旧版本>\`（每个文件都记 sha256），并且：
  - 执行器在两轮健康探测都探不到服务时，**自动**还原这些文件、重启服务、再探一次；
  - Web UI「配置 → 自动升级 → 版本回滚」也能**手动**一键回退到某个备份版本（服务会重启，约 15 秒）。
- **回滚只动代码**：`config.json`、密码、配置方案**都不动**（备份里那份 `config.json` 只供你人工比对）。
  备份保留 7 天、至少留最新 2 份；卸载时一并清掉。
- **安全兜底**：备份被改坏、清单缺失、版本对不上、清单里文件名带路径分隔符 → 一律**拒绝回滚**
  且不写任何文件（宁可不动，也不写出一套「半新半旧」的代码）。
- 顺带修掉一个陷阱：升级后的启动自检原先「找不到旧式备份就直接跳过」，换备份方案后会把
  **升级结果确认、AppExit 自愈、托盘自启项对齐全部跳过** ✗ —— 现在照常执行。

### ✨ 新增（相对 v2.0.9.1）
- **升级收尾改探 HTTP 健康端点**：自动升级跑完安装器后，执行器会用随包内嵌的 Python 探一次
  `http://127.0.0.1:<你的端口>/api/health` —— 只有拿到 `{"ok": true}` 才算「服务真的活了」。
  此前只看 `sc query`，而那是 nssm 的 wrapper：里面的 Python 崩了它照样显示 RUNNING
  （`AppExit=Ignore`：不重启也不报错），所以「升级把服务弄挂了」以前要等你自己发现 ✗。
- **探不到就自动重启重试**：先 `sc stop` + `sc start` 重启一次服务，再给一个窗口重探。
- **失败会留下明确告警**：结论写进 `logs\upgrade.log`（中文、带时间戳）。
  服务真起不来时 Web UI 也打不开，**那行日志就是唯一的告警面** ——
  托盘右键「打开日志目录」即可看到，里面会写明「服务可能没起来」与下一步该看哪个日志。
- **顺手修掉一个从 v2.0.4.2 起就在的老坑**：升级记录里的 `installer_rc=`（安装器退出码）其实
  **从来没真正写下来过** —— `echo installer_rc=0>"…"` 里的数字紧贴 `>`，cmd 会把它当成
  「句柄 0 重定向」→ 文件被写空、文本跑进 stdout ✗，于是「安装器非 0 退出码就告警」那条
  一直是死代码。现在改成把重定向写在命令前面，退出码正常落盘，装失败时日志里能看见它。
- 探针自包含（只用标准库、不读你的配置以外的东西、不走系统代理），跑完自删；
  内嵌 Python 或探针缺失时自动**退回旧判据**（不影响升级本身）。

> ⚠️ **如果你装过 v2.0.8.0 且 Web UI 打不开 / 托盘说「服务未响应」**：
> 重新运行本安装包即可恢复（会自动停服务 → 补齐文件 → 再启动服务；配置与密码不变）。

### 🔴 紧急修复（相对 v2.0.8.0）
- **修「升级时安装中途回滚把安装弄坏」**：托盘进程锁着 `{app}\python\libcrypto-3.dll`，
  安装器替换它失败后静默模式会 Abort 并回滚 ✗ —— 结果新脚本已就位、新增的 `metrics.py`
  被回滚删掉，服务启动即崩、Web UI 端口消失。现在安装器**在写任何文件之前先请走托盘**
  （只匹配「tray.py + 本安装目录」的进程，不误伤别的程序），并且**可选模块缺失时服务降级运行**
  （只是少一块面板，不影响登录与页面）。

> ⚠️ **装过 v2.0.9.0 且 Web UI 打不开 / 托盘说「服务未响应」的话**：重新运行本安装包即可恢复
> （配置、密码、方案都不动）。

### 🔴 紧急修复（相对 v2.0.9.0）
- **修「升级后服务起不来」**：v2.0.9.0 在服务主流程里多写了一句 `import protocol as _protocol_mod`，
  而 Python 里**函数内的 import 会让该名字在整个函数里变成局部变量** ✗ → 同一函数里更早的
  `_protocol_mod._attach(...)` 直接 `UnboundLocalError` → 服务启动即退 ✗（nssm 配的是
  `AppExit=Ignore`，不会自动重启，所以表现成"服务在跑、网页打不开"）。
  已删掉该行，并加静态守卫：服务里出现「函数内 import 模块别名」一律判失败。

### ✨ 新增（相对 v2.0.8.1）
- **配置方案**：给「教室 / 宿舍 / 家里」各存一套位置相关设置（认证网关、检查间隔、
  网络位置守卫白名单），配置页一键切换；填了「自动匹配的 Wi-Fi 名」的方案还能在打开
  「按 Wi-Fi 名自动切换」后**自动切换**（默认关）。
- **账号、密码、升级设置不会进方案**，切换方案也不动它们 —— 换的只是"哪儿该不该登录"。
- 新增 `GET /api/profiles` 与 `POST /api/profiles/save|activate|delete|auto` 四个写接口
  （老接口与老配置完全不受影响）。

### ✨ 新增（相对 v2.0.7.1）
- **连接质量面板**：状态页新增「在线率（近 7 天）/ 掉线重登 / 平均恢复耗时 / 当前延迟」
  与一张近 7 天柱状图。数据全部从**已有日志**现算，不新增状态文件 —— 服务重启不清零、
  升级不丢数据。延迟量的是到校园网关的 TCP 握手（校园网常禁 ping）。
- 接口 `GET /api/metrics?days=7`（1–30 天）；面板属于锦上添花：日志被删、参数非法、
  统计出错都只在面板上显示空白，**不影响状态页其它部分**。

### 🔧 修复（相对 v2.0.7.0）
- **升级后托盘会自己换上新代码**：以前升级只换了磁盘上的文件，正在跑的托盘还留在内存里的
  旧版本 —— 于是像「睡醒 / 换网立刻重连」这种新功能要等到下次注销 / 重启才生效 ✗。
  现在托盘盯着自己的脚本指纹（`mtime` + 大小），一变就**先放开单实例锁 → 起新进程 → 自己退出**；
  万一新进程起不来，会把锁拿回来继续跑（只记一行日志，不会反复重试）。

### ✨ 新增（相对 v2.0.6.3）
- **睡醒 / 换网之后立刻重连**：以前合盖睡一觉、插网线、换 Wi-Fi 之后，服务可能要等到下一次
  周期检查（默认 30 分钟）才补上登录 ✗。现在托盘盯着这两类事件 —— 系统唤醒（等 4 秒让网卡
  连上）与网络地址变化（立刻）—— 一到就触发一次登录检查。
- 事件有 5 秒去抖（唤醒时电源 + 无线 + DHCP 常常连着来）；拿不到事件时自动退化成原来的
  10 秒轮询，不会因为新功能变脆弱。

### 🔧 修复（相对 v2.0.6.2）
- **升级 / 检查按钮不再「假成功」**：先点「立即检查更新」、紧接着点「立即升级」时，
  第二个请求会被升级锁挡掉，但接口一律先回「已提交」✗ —— 界面提示「升级已启动」，
  实际什么都没发生。现在两个入口**先探锁再回车**：忙就回 409 + 当前进度
  （「任务进行中（检查 GitHub 最新版本...），请稍候再试」），空闲才回「已提交」并真的开跑。

### 🔧 修复（相对 v2.0.6.1）
- **自动升级上来的用户，托盘也会自启了**：之前从旧版升级上来时，安装器不知道新加的
  「托盘」任务，启动项会被跳过 ✗。现在改由**服务每次启动对齐**（安装器把开关记进注册表，
  服务据此建 / 修 / 删启动项）—— 不论你从哪个版本升上来都能自愈。

### 🔧 修复（相对 v2.0.6.0）
- **托盘自启项改挂 `HKLM`**：原来是 `HKCU`，而自动升级以 SYSTEM 身份运行安装器 →
  会写进 SYSTEM 的配置单元，真实用户登录时托盘**不会自启**。现在对每个登录用户都生效。
- **卸载后不再留孤儿图标**：安装目录里找不到自己的脚本（连续两次轮询）时托盘自行退出。

### ✨ 新增：托盘图标 + 断线通知
- 装完会多一个**通知区图标**（默认随开机启动，安装向导里可取消勾选）。掉线、恢复、
  服务未响应时会弹**气泡提醒**，不用再自己盯着网页看。
- 右键图标：**打开配置页** / **立即登录** / **打开日志目录** / **退出托盘**；双击图标打开配置页；
  鼠标悬停看当前状态（含当前 Wi-Fi 名）。
- 通知有**防刷屏**：刚开机不弹；偶发一次连不上服务不弹（连续 3 次 ≈30 秒才报「服务无响应」）；
  同一状态不重复弹。
- 它是个独立的小程序（`tray.py`，随登录会话运行）—— 服务本身跑在后台会话里，**没法直接弹通知**。
  只用管理员权限才能在 Program Files 写日志，所以托盘自己的日志在
  `%LOCALAPPDATA%\DrcomAutoLogin\tray.log`。
- 接口、配置结构、服务名、`AppId` 全未动（`PATCH` +1），老配置与升级路径不受影响。

## 用户机器验证步骤（装包后跑）

```
Get-Service DrcomAutoLogin | Select-Object Status, StartType
(Invoke-WebRequest http://127.0.0.1:8848/api/config -UseBasicParsing -TimeoutSec 10).StatusCode   # 必须是 200，且不能挂住
Get-Content "D:\Program Files\DrcomAutoLogin\logs\service_stderr.log" -Tail 30
Get-Content "D:\Program Files\DrcomAutoLogin\logs\campus_login.log" -Tail 50 | Select-String -Pattern "NameError|ModuleNotFound"
Get-Content "D:\Program Files\DrcomAutoLogin\logs\upgrade.log" -Tail 20
```

**预期**：`Status=Running`；`/api/config` 立刻 200（配置页能读到值、保存立即生效）；
stderr 无 `ModuleNotFoundError`；`campus_login.log` 无 `NameError`；
`upgrade.log` 不再出现「几十秒一轮的下载 → 装 → 重启」死循环。
自动升级过的话，`upgrade.log` 里还应看到
`升级执行器结果：installer_rc=0 / service=RUNNING / health=OK`（前两项是 v2.0.4.2 的退出码与
服务状态回报，`health=` 是 v2.0.10.0 新增的 HTTP 健康探测结论 ——
`OK` 表示服务真的答上了 `/api/health`，比 `sc query` 可信）。
若这里是 `health=FAIL`，同一份日志里还会有一行「升级看门狗：HTTP 健康检查未通过」写明原因。
